## 当前优先事项

- [x] **完成首轮分项探索。** 2026-10-31完成snapshot/collector/events/full四条件及collector→snapshot反向复核，1200万正式Ping零失败。首次采集组下降20.90%，反向复核仅下降1.02%；完整组与快照组接近。已有日志证明各轮逐Worker连接分配不同，这是未控制的混杂因素，尚不能确认全部差值的根因。见[分项证据](MONITOR_OVERHEAD_DIAGNOSIS.md)。
- [x] **控制逐Worker负载并做小批比较。** 均衡客户端保留每Worker50条连接，六进程同连接预热、屏障起跑，测量前后核验归属；每Worker50万次测量请求。off/full/full/off共800万次零失败，full的QPS中位数下降1.97%、P95上升1.24%，见[新方法与证据](BALANCED_WORKER_BENCHMARK.md)。服务端二进制、总负载和CPU配额保持不变，但计时方法已改变，结果独立归档，不算原九轮的修复后重测。
- [ ] **实现可配置小范围容差。** 用户已认可目标连接数按总并发/Worker数计算，先按±2%设计（200/4为49～51，400/4为98～102），固定均分保留作基准。只在准备阶段筛选，测量期间保持连接，记录实际分配和请求数；整数边界及不能整除规则随实现明确。当前已交付固定配额，范围方案尚未实现，见[方案](BALANCED_WORKER_BENCHMARK.md#已确认下一步按负载计算容差范围)。
- [ ] **冻结新方法后做正式开销确认。** 容差模式验证后，确定同连接预热、屏障计时和预定多轮顺序，再独立验收；保留原5%/10%目标和零失败要求。当前固定配额探索每组两轮，结果保留，不混合新旧方法。

原2026-10-30九轮1800万请求、QPS下降13.70%/P95上升7.47%及未达标判定保留。新探索不是新的正式验收，也不将测量混杂直接当作监控零开销的证明。
