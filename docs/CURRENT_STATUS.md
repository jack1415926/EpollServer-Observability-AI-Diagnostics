## 阶段性成果

项目已形成“TCP指标采集 → HTTP/Web监控 → 事件与实验持久化 → 只读诊断”的完整链路。本轮补齐监控开销的正式验收，完成了功能建设之后的一项关键工程验证。

| 本轮成果 | 实际价值 |
|---|---|
| 找到逐Worker连接分配未受控的测量缺口 | 将总并发相同进一步落实为各Worker负载可核验，提升对照结果的可解释性 |
| 固定均分与可配置容差两种压测模式 | 固定均分用于精确基准，容差模式适配不同总并发和Worker数量 |
| 同连接预热、屏障计时、逐Worker请求统计 | 建连准备与稳态处理分开计时，实际工作量可追溯 |
| 新方法正式九轮通过开销目标 | 1800万测量、90万预热零失败；full的QPS中位数下降0.14%，抽样P95下降0.21% |

这轮主要提升了实验方法和验证能力。TCP/Drogon二进制保持一致，当前同机Debug Ping负载下，完整监控与关闭监控的中位数表现接近。旧九轮和新方法分别归档，详细数字见[正式验收](BALANCED_WORKER_BENCHMARK.md)。

## 主动TCP Ping已交付

已完成“后台探测 → HTTP → 总览页面 → 诊断工具”。设置`EPOLL_MONITOR_TCP_PORT`启用，默认每5秒一次、总超时1秒；结果包括状态、往返耗时、时间和原因。端口与当前Master绑定，HTTP读取缓存，失效或切换实例时清空旧成功结果。

24项探针/HTTP合并回归通过；真实TCP完成“响应正常 → Worker暂停后超时 → 恢复成功”，并验证原故障隔离和整体退出策略。页面桌面、390px窄屏和断开清空通过，可访问性扫描零违规。配置、证据和启动方法见[主动探测交付](TCP_ACTIVE_PROBE.md)。
