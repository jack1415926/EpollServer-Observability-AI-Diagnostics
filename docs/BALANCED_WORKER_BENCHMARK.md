# 固定Worker连接配额的压测尝试

2026-10-31。用户同意尝试在压测端控制每个Worker的连接负载。此前[分项探索](MONITOR_OVERHEAD_DIAGNOSIS.md)发现总并发200时，单Worker观测连接数可能达到65～67，干扰监控开销解释。本批只修改测试客户端与入口，不改变TCP接受连接或业务调度策略。

## 阶段成果

本批修改了压测客户端和入口：按连接归属筛选每Worker50条连接，使用同一批连接预热，通过六进程屏障统一起跑，并记录各Worker请求数。QPS计时排除建连筛选、预热和收尾，TCP/Drogon代码及二进制保持不变。

四轮800万次测量、40万次预热零失败，各Worker每轮完成50万次测量请求。完整监控相对关闭组QPS中位数下降1.97%、抽样P95上升1.24%。旧九轮在未控制逐Worker负载的方法下测得13.70%下降；新旧结果分别保留，本次没有做服务端性能优化。

已实现的是固定配额基准模式。用户随后确认下一步采用按总并发和Worker数量计算的可配置小范围容差，具体见文末；范围模式尚未实现。

## 分配与核验

1. 读取本轮私有TCP实例context，核验Master PID/start_ticks、Worker PID/start_ticks及父子关系、目标端口和Worker数。
2. 建立有数量/期限上限的候选IPv4连接，通过`/proc/MASTER/net/tcp`的完整四元组及inode，与各Worker的`/proc/PID/fd`匹配，识别已接收连接归属。共享监听FD不参与已接收连接归属判定。
3. 保留每Worker50条连接，关闭多余连接，不足时补建；上限为总并发的8倍候选和30秒准备期。达不到配额就失败，不进入测量。
4. 六个客户端进程继承各自分配的连接，在同一批连接上预热。200个客户端线程与控制器参加同一个跨进程屏障，预热结束后再核验归属，并统一释放测量。
5. 每连接测量10000次Ping；结束时暂留连接，控制器再次核验归属，再释放客户端关闭连接、聚合结果。每Worker有客户端侧50万次请求计数及失败统计。

同一组配额、协议和计时规则用于所有比较条件。PID/归属变化、预热错误、超时或请求未完成不能当作有效零失败测量；客户端及TCP实例按本轮归属清理。权限不足时失败，不猜测连接归属。

此方法仅支持同机Linux IPv4、本用户可读取的Worker FD及有响应超时的socket模式，使用显式fork客户端上下文；不需要特权网络规则、服务端新接口或自动调整生产调度。50条同质Ping连接控制了本次工作量分配，不保证CPU瞬时读数相同，也不代表真实业务请求成本相等。

## 新计时及兼容边界

QPS计时从测量屏障释放前开始，到全部客户端线程完成测量屏障结束；排除候选连接筛选、客户端进程启动、同连接预热、测量后的归属检查、结果序列化及进程收尾。屏障不能消除实际调度差，因此另记`client_start_skew_ms`。预热和测量复用连接，与旧版分别新建连接的口径不同。

原有无配额模式、协议校验、延迟抽样和失败分类保留；收发循环提取为`run_connected`供两种入口复用。均衡结果增加`allocation`，记录三次归属核验、候选/丢弃数、客户端PID、逐Worker请求统计、测量时间窗和计时方式。它是新的实验方法，不能用与旧九轮的数字差额宣称服务端提速或监控问题已修复。

当前网页/MySQL实验schema不能表达这些配额和计时元数据。准备导入时明确拒绝均衡结果，保留独立JSON证据；本批不扩展产品数据库/API/schema。旧真实报告的写入/读回预检仍可独立使用。

资源采样器包裹整个客户端，原始资源文件包含准备和预热。若比较测量期资源，应按allocation中的测量开始/结束时间窗筛选；不能把整个资源摘要当作纯测量区间。full组轮询也可能覆盖连接筛选期，配额验证应结合测量时间窗解释。

最小真实FD归属探针通过；共享监听FD误判在扩大实现前定位并修复。15项均衡/协议/导入检查通过，包含真实多进程配额、预热/起跑/结束屏障、错误预热不进入测量、不可满足配额有界失败及客户端回收。

## 已确认下一步：按负载计算容差范围

用户认可采用“目标值随负载计算，允许小范围偏差”的方案，后续作为常规对照模式；固定均分模式保留为精确基准。

```text
目标连接数 = 总并发 / Worker数量
允许范围 = 目标连接数 ± 可配置容差
```

先按±2%设计：200并发/4 Worker为49～51条，400并发/4 Worker为98～102条。总连接数仍须满足目标并发，整数边界及不能整除时的分配规则在实现时明确。

准备阶段补建和筛选连接，全部Worker进入范围后预热并开始测量；测量期间保持选定连接，不通过持续建连/断连调整分布。结果记录实际范围、逐Worker分配和请求量。范围随负载计算，与测量期不断调整范围是两回事；后者留作独立的动态负载场景。

**本次只记录方案，不把它标为已实现。** 下一批增加容差选项及范围核验，保持现有协议、同连接预热和屏障计时，再冻结方法做预定多轮正式对照。
