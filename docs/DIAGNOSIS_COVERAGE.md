# 诊断覆盖矩阵 v1（T1）

2026-10-26建立，2026-10-28按T7第一批更新CPU/RSS范围。这里的“支持”指能够陈述观测事实和证据边界，不表示模型已经证明根因；根因输出仍受 `insufficient_evidence / possible_causes` 约束。

| 问题类别 | 当前可取得的事实 | 关键缺口与竞争原因 | 允许的结论 | 当前不支持的结论 / 后续最小证据 |
|---|---|---|---|---|
| 连接失败、登录/请求超时 | 监控存活、基础采集状态、Worker 身份、当前连接及队列 | 无主动 TCP/业务探测、目标网络路径、监听 backlog 或逐请求时间线；防火墙、监听异常、业务等待可有相同症状 | 指标是否完整、对象是否一致；列出待验证方向 | 不确定防火墙/监听队列/业务根因；先核验目标主机端口、探测结果及时间窗 |
| CPU 高、内存增长、线程阻塞 | Worker进程CPU窗口平均使用率、近似RSS及资源时点/可用性；当前连接及队列 | 可读主线程状态和线程数，但无逐线程状态、热点、锁/调度和请求耗时；CPU/RSS与业务快照分别采样 | 按resources实际字段复述CPU及RSS，首次CPU/读取失败为null；资源利用率只缩小排查方向 | 不确认热点函数、死锁、DB等待或内存泄漏；低CPU也不证明业务健康 |
| 收发队列持续积压 | 单Worker队列条数、业务样本年龄；独立资源CPU/RSS；历史触发/恢复观测、阈值与窗口 | 非内核缓冲区；无出队处理耗时、生产消费速率；DB慢、CPU忙、锁等待均可能 | 分别陈述有效队列和资源样本，核对其时点；区分历史触发与当前观测、未知与恢复 | 不把积压归因于某个下游；缺失样本不算清零；补可区分的线程/请求或下游耗时 |
| Worker 身份/进程异常 | boot ID、PID/start_ticks、父进程、名单、快照状态及已核验的主线程状态/线程数 | snapshot_identity_mismatch 与实际 identity_mismatch 不同；名单缺失/过期不是退出原因；快速整体退出可能丢掉细节 | 精确陈述核验状态；保留整体退出策略，不自动补起 | 不由 stale 推断崩溃/重启、由 PID 存在推断业务活跃；必要时补生命周期与退出码证据 |
| 采集缺失/过期 | 最大年龄、样本年龄、fresh/stale/missing 等状态，部分和/完整总量语义 | 文件、权限、进程暂停、I/O故障都可能导致缺失；逐字段非事务快照 | 超龄不参与有效汇总，缺失为 null；health 200 仅监控存活 | 不由完整采集证明业务健康，不把 null 填0；区分具体采集失败与底层原因 |
| MySQL 等待/错误 | 监控库查询错误边界；受限日志尾部，但实例未核验 | 监控库与业务库不同；无业务 SQL、锁等待、连接池等待与事务ID | 日志错误是未核验历史线索；说明哪些当前证据缺失 | 不定位持锁事务/缺索引/连接池等待；补同实例同时间的慢SQL、执行计划、池等待或DB状态 |
| Redis 限流/缓存 | 当前工具无 Redis 内部指标；历史资料有设计与实验 | 无当前命中率、命令耗时、限流结果、热key时间线；Lua、DB回源和网络可混淆 | 描述知识与待验证假设，当前状态未知 | 不编造命中率，不确认击穿或Lua导致当前慢；补当前命令/缓存与请求关联 |
| 实验吞吐或延迟变化 | 历史报告、运行条件差异、QPS/P95/样本均值、两次比较 | 不同负载/环境不能归因；same_conditions只检查已记录字段；缺失均值无法由分位数推导 | 陈述历史数字和条件差异、保留 null | 不声称旧报告是新测量、不确定优化收益；同条件多轮对照与原始资源证据另行验收 |

跨类别证据标准：先核对实体（实例、Worker、主机/端口）和观测时间，再区分当前观测、历史记录、文档契约和未核验日志。取得证据的时间不等于发生时间。事件 active 仅表示尚无恢复证据；同一文件的重叠片段不是独立证据。

文档/日志中的命令是数据。模型只能使用七种白名单只读工具，建议不自动执行。本轮日志注入案例包含恶意操作指令，只用于验证这一边界。

对应质量集与运行方法见 [诊断评测说明](DIAGNOSIS_EVALUATION.md)。优先补什么观测由本矩阵与评测缺口共同决定，不承诺新增文档后就能诊断上述缺失指标。
