# Linux子进程状态：停止、终止与回收

来源：Linux man-pages `wait(2)`（含waitpid），本机6.17原始手册；页面日期2026-02-08，核对日期2026-10-27。
一手入口：[wait(2)](https://man7.org/linux/man-pages/man2/waitpid.2.html)。在线6.19页面日期2026-06-05；这里只交叉核对下列稳定语义，不声称两个版本逐字一致。本文为项目助手要点整理。

## waitpid返回需要解释状态

- 子进程的停止、继续和终止是不同状态变化。检查到状态变化不等于它已经退出。
- WIFSTOPPED表示因信号停止；WIFCONTINUED表示由SIGCONT继续。WIFEXITED用于正常终止，WIFSIGNALED用于因信号终止；宏的含义不能互换。停止/继续报告还受wait选项等条件影响。
- 终止但尚未被父进程回收的子进程可能处于僵尸状态；PID仍存在不代表它还在执行业务。

## 本项目的退出证据边界

这些是父进程等待子进程的接口语义，不能要求独立监控进程用waitpid回收任意Worker。现有七种诊断工具没有提供Master的原始wait状态、退出码或导致终止的信号。

当前项目保留Worker意外退出时整体停止的策略，不自动补起；这是本项目决策，不是Linux内核规定。快照过期、名单条目仍存在或active采集事件均不能替代退出状态证据，也不能确定退出原因。见[事件规则](../STAGE_4_EVENTS.md#规则与证据)。
