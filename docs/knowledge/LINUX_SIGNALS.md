# Linux信号：SIGSTOP暂停与SIGCONT继续

来源：Linux man-pages `signal(7)`，本机6.17原始手册；页面日期2026-02-08，核对日期2026-10-27。
一手入口：[signal(7)](https://www.man7.org/linux/man-pages/man7/signal.7.html)。在线6.19相关条目交叉核对；下文为项目助手整理的要点，不是官方原文或运行观测。

## SIGSTOP与SIGCONT的语义

- SIGSTOP使进程暂停执行，不是进程终止。SIGSTOP不能被捕获、忽略或屏蔽，不能为它注册一个有效的清理处理函数。
- SIGCONT可使已暂停的进程继续执行；继续执行与新建/重启进程不同。
- 发送继续信号不证明某个业务请求成功；操作系统信号语义不能代替应用健康检查。

## 本项目中的快照过期边界

由手册机制与本项目后台采样设计推导：Worker暂停后采样也可能停止，已有文件会随时间变旧；刚暂停时快照仍可能fresh。该推导不是对某个当前Worker已收到SIGSTOP的观测。

仅有stale表示样本超龄，不能确认SIGSTOP、崩溃、锁等待或文件发布故障中的某一种。需要同一启动身份、同一时间窗口的进程/信号或发布错误证据。

现有诊断工具不发送信号；本文中的SIGSTOP/SIGCONT仅用于解释机制和已记录案例，不授权执行。项目契约见[采集语义](../STAGE_1_COMPLETION.md#读取和汇总语义)。
